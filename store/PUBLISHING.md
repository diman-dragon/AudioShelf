# Публикация AudioShelf в Google Play — пошагово

Всё, что можно было подготовить в репозитории, уже лежит здесь. Ниже — то, что делаете вы руками.
Состояние проверено 15.10.2026; правила Google меняются, сверяйтесь с Play Console.

## Что уже готово

| Что | Где |
|---|---|
| Тексты карточки (RU, EN) | `store/listing/<язык>/title|short|full|whatsnew.txt` |
| Иконка 512×512 | `store/graphics/icon-512.png` |
| Feature graphic 1024×500 | `store/graphics/feature-graphic-*.png` |
| Скриншоты 1080×1920, светлая/тёмная тема, RU/EN | `store/screenshots/` (на демо-данных, только книги и музыка public domain) |
| Политика конфиденциальности | `docs/index.html` |
| Ответы для Data safety и деклараций | `store/data-safety.md` |
| Подпись релиза и сборка AAB | `android/app/signing.gradle`, `.github/workflows/release-aab.yml` |

## Шаг 0. Решите до первой загрузки (потом не изменить)

1. **applicationId** сейчас `com.audioshelf.app`. После публикации менять нельзя. Если хотите свой домен — замените в `android/app/build.gradle`, `capacitor.config.*`, `AndroidManifest.xml` и пакете Java (`com.audioshelf.app`) до загрузки.
2. **Версия.** Сейчас 0.9.4 (versionCode 904). Для первого релиза логично 1.0.0 (versionCode 10000): поднимите версию по правилам проекта.
3. **E-mail в политике:** в `docs/index.html` замените `[ВАШ E-MAIL]` и `[YOUR E-MAIL]`.

## Шаг 1. Аккаунт разработчика

1. https://play.google.com/console → создать аккаунт, разовый взнос **25 $**.
2. Верификация личности (документ, адрес, телефон). Тип: личный или организация.
3. Личный аккаунт, созданный после 13.11.2023, **обязан пройти закрытое тестирование**: минимум **12 тестировщиков**, подписанных **14 дней подряд**, затем заявка на доступ к продакшену. Google смотрит на реальную активность тестеров. У организационного аккаунта этого требования нет.
4. Android developer verification (регистрация разработчиков): с 30.09.2026 в Бразилии, Индонезии, Сингапуре и Таиланде, глобально — с 2027. Приложения из Play входят в охват; следите за письмами Play Console.

## Шаг 2. Ключ загрузки и секреты GitHub

```bash
keytool -genkeypair -v -keystore upload.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 upload.jks > upload.jks.b64      # macOS: base64 -i upload.jks
```

В репозитории: Settings → Secrets and variables → Actions → New secret:

| Секрет | Значение |
|---|---|
| `UPLOAD_KEYSTORE_BASE64` | содержимое `upload.jks.b64` |
| `UPLOAD_KEYSTORE_PASSWORD` | пароль хранилища |
| `UPLOAD_KEY_ALIAS` | `upload` |
| `UPLOAD_KEY_PASSWORD` | пароль ключа |

Файл `upload.jks` и пароли **храните в двух надёжных местах** вне репозитория (`*.jks` в .gitignore). При потере ключа загрузки его можно сбросить через поддержку Play, но это долго.

## Шаг 3. Собрать AAB

GitHub → Actions → **Release AAB** → Run workflow. Результат — artifact `AudioShelf-<версия>-aab` с файлом `AudioShelf-<версия>.aab`.
Если секретов нет, workflow остановится с подсказкой на этот файл.
Локально: задайте переменные `AUDIOSHELF_KEYSTORE_FILE`, `AUDIOSHELF_KEYSTORE_PASSWORD`, `AUDIOSHELF_KEY_ALIAS`, `AUDIOSHELF_KEY_PASSWORD` (или файл `android/keystore.properties`) и выполните `cd android && ./gradlew bundleRelease`.

Проверьте: `targetSdkVersion = 36` в `android/variables.gradle` (обязательно для новых приложений с 31.08.2026).

## Шаг 4. Политика конфиденциальности (GitHub Pages)

Repo → Settings → Pages → Source: *Deploy from a branch*, ветка `main`, папка **/docs**. Через минуту страница откроется по `https://<логин>.github.io/<репозиторий>/`. Этот URL — в карточке приложения. Английская версия — `#en`.

## Шаг 5. Создать приложение в Play Console

1. Create app: имя **AudioShelf** (из `store/listing/ru-RU/title.txt`), язык по умолчанию — русский, тип «Приложение», «Бесплатное».
2. **Главная страница** → пройти пункты «Настроить приложение»:
   - политика конфиденциальности — URL из шага 4;
   - доступ к приложению — «ограничений нет»;
   - реклама — нет; встроенные покупки — есть (см. шаг 5а);
   - рейтинг контента — анкета IARC (всё «нет») → категория «Музыка и аудио»;
   - целевая аудитория — 18+;
   - Data safety — по `store/data-safety.md`;
   - декларация **Foreground service → mediaPlayback** с видео (описание в `store/data-safety.md`);
   - остальное (новости, COVID, финансы, здоровье, госприложение) — «нет».
3. **Основная карточка**: тексты из `store/listing/ru-RU/`; добавьте перевод English (United States) из `en-US/`. Иконка, feature graphic, скриншоты (минимум 2, лучше 7 — все лежат в `store/screenshots/<язык>/<тема>/`; для карточки достаточно светлой или смешанной темы).
4. Приложение (контакты): e-mail, сайт (можно страницу политики).

## Шаг 5а. Товары для встроенных покупок (обязательно, иначе покупки не работают)

Нужен платёжный профиль Google (Play Console → Настройка → Платёжный профиль). Затем **Монетизация → Товары → Разовые товары** (One-time products), создайте 4 товара. **ID должны совпадать с кодом** (`src/billing/products.js`, `BillingProducts.java`):

| ID | Что это | Цена (как выбрано) |
|---|---|---|
| `premium` | Премиум: эквалайзер и нормализация, покупается один раз | любая, на ваше усмотрение (в браузерной заглушке показано $9.99) |
| `tip_small` | «Чашка чая» | 0,99 $ |
| `tip_medium` | «Чайник» | 2,99 $ |
| `tip_large` | «Самовар» | 4,99 $ |

Все четыре — статус **Активен**, регионы цен задайте автоматически от базовой цены. Названия и описания — на русском и английском (например «Премиум» / «Premium», «Чашка чая» / «Cup of tea»). Чаевые приложение «погашает» (consume) само сразу после оплаты, поэтому их можно покупать много раз; Премиум подтверждается (acknowledge) в течение 3 суток автоматически, иначе Google вернёт деньги.

Как проверить покупки до публикации: Play Console → Настройки → **Лицензионное тестирование** → добавьте свой e-mail (тестовые покупки без списания) и установите сборку **из трека тестирования** (покупки не работают с APK из GitHub, подписанного другим ключом, и с неопубликованного приложения). Проверьте: покупку Премиума (замок исчезает, эквалайзер работает), отмену, повторный запуск, чаевые трёх размеров, возврат (отмена в Play Console → Премиум пропадает после следующей проверки).

## Шаг 6. Закрытое тестирование → продакшен

1. Testing → Closed testing → создать трек, список тестеров (e-mail или Google Group), загрузить AAB, **включить Play App Signing** (по умолчанию для новых приложений), заполнить «Что нового» из `whatsnew.txt`.
2. Разослать ссылку-приглашение 12+ людям; попросить **принять приглашение и установить**, держать 14 дней подряд и реально пользоваться.
3. Смотрите **Pre-launch report** — ошибки запуска, падения, доступность; исправьте и загрузите новую версию (versionCode должен расти).
4. Через 14 дней: Dashboard → «Подать заявку на доступ к продакшену» (опишите, как тестировали и что исправили).
5. После одобрения — Production → создать релиз с тем же или новым AAB → отправить на проверку (часто 1–7 дней, у новых аккаунтов дольше).

## Что не проверено (честно)

- Сборка Gradle и работа на устройстве (эквалайзер, измерение громкости, таймер сна, шторка) в среде разработки не проверялись — прогоните APK на реальном телефоне до отправки.
- Релизная сборка не минифицируется (`minifyEnabled false`) — это безопасно, но размер больше. Включать R8 стоит только после проверки на устройстве.
- Покупки (Google Play Billing 8.0.0) написаны по документации, но не запускались: проверьте весь цикл на устройстве через лицензионное тестирование. Если Play потребует более новую версию библиотеки (сейчас актуальна 9.x), поменяйте `billingVersion` в `android/variables.gradle` и сверьте API по руководству по миграции.
- Премиум проверяется на устройстве по ответу Google Play (без собственного сервера): достаточно для такого приложения, но технически подкованный пользователь может обойти блокировку.
- Разрешение `INTERNET` осталось в манифесте (стандарт Capacitor).
- Скриншоты сделаны в браузере на демо-данных, не на устройстве; Google допускает это, но на реальном телефоне лучше переснять.
